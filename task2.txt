    TASK 1 - PERSONAL EXPENSE TRACKER CLI

    Create a command-line Personal Expense Tracker that allows a user to add, view, search, summarize, delete, save and reload expense records.

    EXPENSE DATA

    {
        "id": 1,
        "category": "Food",
        "amount": 250.50,
        "description": "Lunch",
        "date": "2026-09-04",
        "tags": ["office", "meal"]
    }

    REQUIRED MENU

    =============================
           EXPENSE TRACKER
    =============================
    1. Add Expense
    2. View All Expenses
    3. Search Expenses
    4. Filter by Category
    5. Calculate Total Expense
    6. Category-wise Summary
    7. Highest Expense
    8. Delete Expense
    9. Save Data
    10. Exit


    FUNCTIONAL REQUIREMENTS

    1. Load previously saved expenses from data/expenses.json when the application starts. If the file does not exist, start with an empty collection without crashing.
    2. Allow a user to add an expense containing category, amount, description, date and one or more tags.
    3. Generate a unique numeric ID for each expense.
    4. Store the active expense data as a list of dictionaries.
    5. Display all expenses clearly.
    6. Search expenses using text entered by the user. The search should be case-insensitive and should be able to match useful textual fields such as category or description.
    7. Filter expenses by category.
    8. Calculate the total amount of all expenses.
    9. Generate category-wise totals using an appropriate dictionary.
    10. Find and display the highest expense.
    11. Delete an expense by ID.
    12. Use a set somewhere meaningful, for example to derive unique categories or unique tags.
    13. Use a tuple somewhere meaningful, for example for supported menu choices, fixed field names or another fixed collection.
    14. Use at least one comprehension.
    15. Use sorted() with a key function to provide at least one useful sorted view, for example highest-to-lowest amount.
    16. Save the latest expense data to JSON.
    17. The program must continue until the user explicitly chooses Exit.
    18. When exiting, ensure the latest valid data is saved.


    MANDATORY FUNCTION DESIGN

    Your solution must be function-oriented. At minimum, your application should have responsibilities equivalent to:

    - load_expenses(...)
    - save_expenses(...)
    - generate_expense_id(...)
    - add_expense(...)
    - validate_amount(...)
    - search_expenses(...)
    - filter_by_category(...)
    - calculate_total(...)
    - category_summary(...)
    - find_highest_expense(...)
    - delete_expense(...)
    - display_expenses(...)
    - main(...)

    You must decide the exact parameters, return values and internal implementation.

    Additional requirements:
    - Important functions must use type hints.
    - Important functions must contain docstrings.
    - At least one function must use a default parameter.
    - Demonstrate *args or **kwargs once in a sensible helper/reporting function.


    VALIDATION AND EXCEPTION HANDLING

    - Amount must be numeric and greater than zero.
    - Category cannot be empty.
    - Description cannot be empty.
    - Expense ID must be valid.
    - Deleting a missing Expense ID must be handled gracefully.
    - Invalid menu choices must not terminate the program.
    - Invalid or malformed JSON must not cause an uncontrolled application crash.
    - Use raise for at least one validation/business rule.
    - Create and use at least one custom exception, for example InvalidExpenseError.
    - Use specific exceptions rather than a blanket except wherever possible.
    - Log unexpected errors with useful context.


    REQUIRED PROJECT STRUCTURE

    expense_tracker/
    |
    |-- main.py
    |-- expense_manager.py
    |-- validators.py
    |-- file_handler.py
    |-- logger_config.py
    |-- exceptions.py
    |-- requirements.txt
    |-- README.md
    |
    |-- data/
    |   `-- expenses.json
    |
    `-- logs/
        `-- app.log


    LOGGING REQUIREMENTS

    Configure logging in logger_config.py. The application should log meaningful events instead of using print() for internal diagnostics. print() is still appropriate for information shown to the CLI user.

    DEBUG - useful diagnostic details.
    INFO - application start/stop, successful add/delete/save/load operations.
    WARNING - invalid user input or recoverable situations.
    ERROR - failed file operations, malformed data or unexpected application errors.
